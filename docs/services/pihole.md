#### DNS-Сервер Pi-Hole
- Расположение: `services/pihole.nix`
- Использующееся опции: `networking.hosts` `services.dnsmasq` `services.pihole-ftl` `services.pihole-web` `services.resolved` `services.nginx.virtualHosts` `systemd.tmpfiles.rules`
- Зависимости: наличие nginx, сгенерированный токен

**Ключевые параметры**:
- `networking.hosts` - настройка доменов для айпи адресов которые находятся внутри локальной сети
- `services.pihole-ftl.settings.dns.domain` - если домен нужен иной то указываем имя домена который используется для этого сервера
- `services.pihole-ftl.settings.dns.interface` - интерфейс сетевой карты может быть иным, настройка меняет сетевую карту
- `services.nginx.virtualHosts."pihole.server.local"` - если для доступа к панели необходим иной поддомен или домен изменен то необходимо изменить его название 

**Описание**:
днс сервер, который может быть настроен для фильтрации трафика по нужным спискам, или собственные доменны внутри локальной сети.

**Принцип**:
Указываются домены которые будут использовать в локальной сети, после чего настраивается Pi-Hole с настройкой списков, подключению по web. Так же настраивается обратный прокси для веб панели и настройка токена вместе с конфигом версии

**Проблема**:
Сама по себе настройка Pi-Hole работает через указание опции которые будут переконвертированны в параметры конфигурации. По этому при стандартном указании токена через `$__file{${config.sops.secrets.token.path}}` ключ не расшифровывается внутри, наоборот эта опция переносится в конфигурационный файл. По этому настройка происходит через указание файла переменных окружения который зашифрован. Но здесь проблема именно в самой настройке ключа и костыльности, иначе здесь не исправляется проблема безопасности.

*Вопросы насчет безопастности и хранения BALLOON ключа в незашифрованном виде игнорируются, в целях безопасности даже такие ключи будут шифроваться.*
